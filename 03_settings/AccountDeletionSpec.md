## 1. Правовая база

### 1.1 Таблица законов и требований

| Закон | Требование | Срок | Последствие нарушения |
|---|---|---|---|
| **GDPR Art.17(1)** | Удалить все персональные данные по запросу | 30 дней | Штраф до €20M или 4% оборота |
| **GDPR Art.17(2)** | Уведомить 3rd-party обработчиков об удалении + де-индексировать из поисковиков | «без излишней задержки» | Штраф |
| **GDPR Art.5(1)(e)** | Не хранить данные дольше необходимого | — | Штраф |
| **CCPA/CPRA §1798.105** | Удалить по запросу калифорнийского пользователя за 45 дней (продление +45 дней) | 45 дней | Штраф $100–750 за пользователя |
| **PIPEDA (Канада)** | Уничтожить или обезличить при закрытии аккаунта | Разумный срок | — |
| **Israel PPL** | Удалить по запросу субъекта | 30 дней | — |
| **App Store §5.1.1(v)** | Пользователь должен иметь возможность удалить аккаунт прямо в приложении | Немедленно (функция) | Отказ в публикации |
| **App Store §5.1.1(v)** | Веб-страница удаления для пользователей без устройства Apple | — | Отказ в публикации |
| **Google Play Data Safety** | Описать в форме Data Safety все типы данных, срок хранения и процесс удаления | До публикации | Отказ в публикации |
| **Google Play Policy** | Ссылка на форму удаления аккаунта в Play Console | — | Удаление приложения |
| **DSA Art.17** | Уведомление пользователя о причине удаления контента/аккаунта (если по решению платформы) | — | Штраф |

### 1.2 Что НЕЛЬЗЯ удалять немедленно (законные исключения)

По закону разрешено хранить до **90 дней** после удаления:

| Категория данных | Срок хранения | Основание |
|---|---|---|
| Данные о транзакциях / платежах | 5–7 лет | Налоговое законодательство (НК РФ, EU VAT Directive, IRS) |
| Данные о мошенничестве / abuse | 90 дней | GDPR Art.17(3)(e) — защита правовых требований |
| IP-адреса входов (security logs) | 90 дней | GDPR Art.17(3)(e) |
| Контент, заблокированный по жалобе | До завершения расследования | DSA Art.17 + GDPR Art.17(3)(b) |
| Данные для ответа на судебный запрос | На период запроса | GDPR Art.17(3)(b) |
| Резервные копии (бэкапы) | 30 дней | GDPR Recital 65 — технически неизбежно |

> ⚠️ Пользователь должен быть информирован об этих исключениях НА ЭКРАНЕ подтверждения удаления.

## 2. Типы аккаунтов и сценарии удаления

### 2.1 Архитектура аккаунтов

```
Пользователь
└── Личный профиль (Personal Profile)  ← ОБЯЗАТЕЛЕН, создаётся первым
    └── Бизнес-профиль (Business Profile)  ← ОПЦИОНАЛЬНЫЙ, привязан к личному
        (может быть несколько бизнес-профилей на один личный)
```

**Ключевое правило:** Бизнес-профиль не может существовать без привязанного личного профиля. При удалении личного профиля все связанные бизнес-профили удаляются автоматически.

### 2.2 Матрица сценариев

| # | Что удаляет пользователь | Что произойдёт | Экраны |
|---|---|---|---|
| **A** | Только бизнес-профиль | Личный остаётся, бизнес удалён | A1 → A2 → A3 → A4 |
| **B** | Личный, когда есть бизнес | Предупреждение → выбор → удаление всего | B1 → B2 → B3 → B4 → B5 |
| **C** | Личный (бизнеса нет) | Стандартное удаление | C1 → C2 → C3 → C4 |
| **D** | Взлом → экстренное удаление | Упрощённый поток через email | D1 → D2 → D3 |

## 3. Сценарий A — удаление бизнес-профиля (личный остаётся)

### Флоу

```
Настройки бизнес-профиля
→ [A1] Экран: «Удалить бизнес-профиль»
→ [A2] Модал: предупреждение + список последствий
→ [A3] Подтверждение (ввод пароля или «DELETE»)
→ [A4] Экран успеха + переход на личный профиль
```

### Экран A1 — точка входа
**Путь:** Бизнес-профиль → Settings → Account → Delete Business Profile

**Отображаемые элементы:**
- Кнопка `Delete Business Profile` (красный текст, не кнопка-блок)
- Расположение: внизу раздела Account Settings, отделена разделителем

### Экран A2 — модал предупреждения

```
┌─────────────────────────────────────┐
│  Удалить «[Название бизнеса]»?      │
│                                     │
│  ⚠️ Это действие необратимо.        │
│                                     │
│  Что произойдёт:                    │
│  ✓ Страница бизнеса будет удалена   │
│  ✓ Подписчики потеряют доступ       │
│  ✓ Активные предложения отменены    │
│  ✓ Профиль удалён из поиска         │
│    (до 30 дней)                     │
│                                     │
│  Ваш личный аккаунт сохранится.     │
│                                     │
│  Что мы сохраним до 90 дней:        │
│  • Данные транзакций (закон)        │
│  • Данные безопасности              │
│                                     │
│  [Удалить бизнес]  [Отмена]         │
└─────────────────────────────────────┘
```

### Экран A3 — подтверждение

```
┌─────────────────────────────────────┐
│  Подтвердите удаление               │
│                                     │
│  Введите пароль от аккаунта:        │
│  [________________________]         │
│                                     │
│  [Подтвердить удаление]  [Отмена]   │
└─────────────────────────────────────┘
```

### Экран A4 — успех

```
┌─────────────────────────────────────┐
│  ✓ Бизнес-профиль удалён            │
│                                     │
│  Удаление данных займёт до 30 дней. │
│  Ваш личный аккаунт активен.        │
│                                     │
│  [Перейти к личному профилю]        │
└─────────────────────────────────────┘
```

## 5. Сценарий C — удаление личного профиля (без бизнеса)

### Флоу

```
Личный профиль → Settings → Account → Delete Account
→ [C1] Модал предупреждения
→ [C2] Подтверждение (пароль)
→ [C3] Экран «30-дневная заморозка» (grace period)
→ [C4] Экран прощания (после истечения grace period или немедленно)
```

### Экран C1 — модал предупреждения (ОСНОВНОЙ ЭКРАН)

```
┌─────────────────────────────────────┐
│  Удаление аккаунта                  │
│                                     │

│                                     │

│  ✓ Все ваши данные будут удалены    │
│  ✓ Ваши посты и комментарии         │
│    удалены                          │
│  ✓ Аккаунт нельзя восстановить      │
│  ✓ Ваш профиль будет удалён из      │
│    поисковых систем (до 30 дней)    │
│                                     │
│  Что мы сохраним на срок до 90 дней:│
│  • Данные для предотвращения        │
│    мошенничества                    │
│  • Данные для соблюдения            │
│    требований закона                │
│  (см. Privacy Policy раздел         │
│  «Хранение»)                        │
│                                     │
│  Введите пароль для подтверждения:  │
│  [________________________]         │
│                                     │
│  [🗑 Удалить аккаунт навсегда]      │
│  [Отмена]                           │
└─────────────────────────────────────┘
```

> Этот экран соответствует скриншоту пользователя (ПОТОК 6 из ProfileSettingsFullSpec.md).

### Экран C2 — grace period (30 дней на восстановление)

```
┌─────────────────────────────────────┐
│  Аккаунт запланирован на удаление   │
│                                     │
│  Дата удаления: [дата + 30 дней]    │
│                                     │
│  У вас есть 30 дней, чтобы          │
│  отменить удаление и войти в        │
│  аккаунт снова.                     │
│                                     │
│  Подтверждение отправлено на:       │
│  [e***@example.com]                 │
│                                     │
│  [Отменить удаление]                │
│  [Выйти]                            │
└─────────────────────────────────────┘
```

> **Grace period — опциональная фича.** Технически App Store и GDPR не требуют 30-дневного grace period. Решение о его реализации принимает продукт-команда. Если реализуется — пользователь должен получить email с возможностью отмены.

## 6. Сценарий D — взлом аккаунта

### Контекст

Если пользователь утверждает что его аккаунт взломан:
- Он не может войти в приложение (потерял доступ)
- Злоумышленник может удалить аккаунт или данные
- Нужен отдельный безопасный поток восстановления/удаления

### Флоу

```
Экран входа → «Не могу войти» → «Подозреваю взлом»
→ [D1] Экран: верификация по email
→ [D2] Экран: выбор действия (заблокировать / восстановить / удалить)
→ [D3] Подтверждение + email-уведомление
```

### Экран D1 — верификация личности

```
┌─────────────────────────────────────┐
│  Защита аккаунта                    │
│                                     │
│  Введите email, привязанный к       │
│  аккаунту:                          │
│  [________________________]         │
│                                     │
│  Мы отправим код подтверждения.     │
│                                     │
│  [Получить код]                     │
│  [← Назад]                          │
└─────────────────────────────────────┘
```

### Экран D2 — выбор действия

```
┌─────────────────────────────────────┐
│  Что вы хотите сделать?             │
│                                     │
│  [🔒 Временно заблокировать         │
│      аккаунт]                       │
│  Никто не сможет войти 24 часа.     │
│  Рекомендуется если вы не уверены.  │
│                                     │
│  [🔑 Восстановить доступ]           │
│  Сбросить пароль и войти снова.     │
│                                     │
│  [🗑 Удалить аккаунт навсегда]      │
│  Все данные будут уничтожены.       │
│                                     │
│  [Связаться с поддержкой]           │
└─────────────────────────────────────┘
```

### Экран D3 — подтверждение удаления при взломе

```
┌─────────────────────────────────────┐
│  Удаление аккаунта                  │
│                                     │
│  Введите код из письма:             │
│  [__ __ __ __ __ __]                │
│                                     │
│  После подтверждения:               │
│  ✓ Все сессии будут завершены       │
│  ✓ Данные удалены в течение         │
│    30 дней                          │
│  ✓ Email с подтверждением отправлен │
│                                     │
│  [Подтвердить удаление]             │
│  [Отмена]                           │
└─────────────────────────────────────┘
```

### Backend-действия при взломе

1. Немедленно инвалидировать **все активные сессии** (все устройства)
2. Заблокировать вход с паролем злоумышленника
3. Отправить уведомление на резервный email (если привязан)
4. Зафиксировать IP последних 10 входов (для support team)
5. При подтверждении удаления — запустить стандартный процесс удаления

## 8. Тексты на каждом экране

### 8.1 Обязательные юридические фразы

Следующие фразы должны присутствовать дословно (или эквивалентно) для прохождения ревью App Store и Google Play:

| Фраза | Экран | Закон |
|---|---|---|
| «Ваш профиль будет удалён из поисковых систем (до 30 дней)» | C1, B3 | GDPR Art.17(2) |
| «Данные для соблюдения требований закона хранятся до 90 дней» | C1, B3, A2 | GDPR Art.17(3), CCPA |
| «Это действие необратимо» | C1, B3, A2 | App Store §5.1.1(v) |
| «Аккаунт нельзя восстановить» | C1, B3 | App Store §5.1.1(v) |
| Ссылка на Privacy Policy | C1, B3 | GDPR Art.13, CCPA |

### 8.2 Email-уведомления (обязательны)

| Событие | Кому | Когда | Содержание |
|---|---|---|---|
| Запрос на удаление подтверждён | Пользователю | Немедленно | Дата удаления, ссылка на отмену (если grace period) |
| Удаление завершено | Пользователю | После завершения | Подтверждение, контакт support |
| Подозрительный запрос на удаление | Пользователю | Немедленно | IP, устройство, ссылка «Это не я» |
| Бизнес-профиль удалён | Пользователю | Немедленно | Название бизнеса, дата |

## 9. Backend-процесс удаления и сроки

### 9.1 Хронология после нажатия «Удалить»

```
Т+0 сек       Пользователь нажал «Удалить аккаунт навсегда»
Т+0 сек       Инвалидация всех активных сессий (logout со всех устройств)
Т+0 сек       Аккаунт переведён в статус PENDING_DELETION
Т+0 сек       Профиль скрыт из всех публичных списков и поиска в приложении
Т+0 сек       Email-подтверждение отправлен пользователю

Т+0..30 дней  [Grace Period — опционально]
              Пользователь может войти и отменить удаление

Т+30 дней     Начало физического удаления данных
(или Т+0      если grace period не реализован)

Т+30 дней     Удалить: профиль, посты, комментарии, лайки, медиафайлы,
              личные сообщения*, связи (друзья/подписчики)
              * сообщения собеседника остаются, но отправитель заменяется
                на «Удалённый пользователь»

Т+30 дней     Запрос де-индексации в Google Search Console,
              Bing Webmaster Tools, Yandex.Webmaster API

Т+30 дней     Уведомить 3rd-party сервисы (analytics, email providers,
              CDN) об удалении данных пользователя [GDPR Art.17(2)]

Т+30..90 дней Хранить в изолированном хранилище (не доступно production):
              - Security logs (IP входов, device fingerprints)
              - Anti-fraud data (паттерны поведения без PII)
              - Транзакционные данные (если есть платежи)

Т+90 дней     Физическое уничтожение всех оставшихся данных
              Удаление из резервных копий (при плановой ротации бэкапов)

Т+90 дней     Email «Удаление завершено» пользователю (опционально, но
              рекомендуется для GDPR Art.17 compliance)
```

### 9.2 Статусы аккаунта

| Статус | Описание | Что видит пользователь | Что видят другие |
|---|---|---|---|
| `ACTIVE` | Активный аккаунт | Всё нормально | Профиль виден |
| `PENDING_DELETION` | Запрошено удаление, grace period | Баннер с обратным отсчётом | Профиль скрыт |
| `DELETING` | Идёт физическое удаление | Нет доступа | Профиль не виден |
| `DELETED` | Удалён, данные в карантине 90 дней | Нет доступа | «Пользователь не найден» |
| `PURGED` | Полностью уничтожен | — | — |

### 9.3 Что происходит с данными других пользователей

| Тип данных | Действие |
|---|---|
| Сообщения в чатах | Сообщения остаются у собеседника. Имя заменяется «Deleted User», аватар → серая заглушка |
| Комментарии к чужим постам | Удаляются полностью |
| Лайки на чужие посты | Удаляются (счётчик уменьшается) |
| Упоминания @username в чужих постах | Username заменяется «[deleted]» |
| Совместный контент (co-authored) | Удаляется доля удалённого пользователя |

## 10. Де-индексация из поисковиков (GDPR Art.17(2))

### 10.1 Требование закона

GDPR Art.17(2): «Когда контролёр сделал персональные данные общедоступными и обязан удалить их... он принимает **разумные шаги** для информирования контролёров, обрабатывающих эти данные, о том, что субъект запросил удаление».

На практике — запрос де-индексации в поисковые системы.

### 10.2 API для де-индексации

| Поисковик | API / Инструмент | Срок обработки |
|---|---|---|
| **Google** | Google Search Console Removals API (`/urlInspection/index:inspect` + removal request) | 24–72 часа |
| **Bing / Microsoft** | Bing Webmaster API (`/v1/site/{siteUrl}/urlinfo`) | 24–72 часа |
| **Yandex** | Yandex.Webmaster API (AddHost + удаление страниц) | 2–5 дней |
| **DuckDuckGo** | Не имеет публичного API; использует индекс Bing | Автоматически после Bing |

### 10.3 Backend-задача де-индексации

```
При переходе аккаунта в статус DELETING:
1. Получить список всех публичных URL профиля:
   - /profile/{username}
   - /profile/{username}/posts
   - /business/{businessSlug} (для каждого бизнес-профиля)
2. Для каждого URL отправить запрос де-индексации в:
   - Google Search Console Removals API
   - Bing Webmaster API
   - Yandex Webmaster API
3. Сохранить requestId каждого запроса в audit log
4. Проверить статус через 72 часа, повторить если не выполнено
```

### 10.4 Что сообщить пользователю

На экране C1 (и B3):
> «✓ Ваш профиль будет удалён из поисковых систем (до 30 дней)»

В Privacy Policy (раздел «Удаление данных»):
> «После удаления аккаунта мы направляем запросы на де-индексацию вашего профиля в основные поисковые системы. Фактическое время удаления из кэша поисковика составляет от 1 до 30 дней в зависимости от поисковой системы.»

## 11. Веб-форма удаления (требование App Store + Google Play)

### 11.1 Требование

- **App Store §5.1.1(v):** Должна быть веб-страница для удаления аккаунта — для пользователей, которые не имеют доступа к устройству Apple.
- **Google Play:** В Play Console обязательна ссылка на форму удаления данных.
