## ЧАСТЬ 1. БЕЗОПАСНОСТЬ (Safety)

### §1.2 User-Generated Content (UGC) — Пользовательский контент

> **Это один из самых строгих разделов для социальных сетей. Нарушение = автоматический отказ.**

Официальное требование: приложения с UGC или социальными функциями **ОБЯЗАНЫ** включать:

| # | Требование §1.2 | Реализация в Bestme | Статус |
|---|---|---|---|
| 1 | **A method for filtering objectionable material** — фильтрация неприемлемого контента до публикации | Content moderation + user reports | ⚠️ Нужна документация в Settings Spec |
| 2 | **A mechanism to report offensive content** — механизм жалоб на контент + своевременная реакция | Help → Report a problem | ✅ |
| 3 | **The ability to block abusive users** — возможность заблокировать агрессивных пользователей | Privacy → Blocked Accounts → Block user | ✅ |
| 4 | **Published contact information** — опубликованные контактные данные для пользователей | Help & Support → Contact | ✅ |

> **Критически важно**: отсутствие хотя бы ОДНОГО из 4 пунктов = **автоматический отказ Apple**. Все 4 должны быть задокументированы в App Review Notes при подаче.

**Дополнительные ограничения §1.2:**
- Приложения для UGC не должны деградировать в порнографические платформы / чат-рулетки / анонимные чаты → ⚠️ Нужна внутренняя модерационная политика
- «NSFW» контент должен быть скрыт по умолчанию (off by default) → ✅ Privacy by Default

### §1.2.1 Creator Content

| Требование | Статус |
|---|---|
| Механизм идентификации контента, превышающего возрастной рейтинг приложения | ❌ Нужен если есть Creator-программа |
| Ограничение доступа несовершеннолетних через возрастную верификацию | ⚠️ Date of birth есть, но creator-gate нужен отдельно |

### §1.3 Kids Category — Детская категория

> Bestme — **только для 18+**. Требования §1.3 (Kids Category) не применяются. Age gate на экране регистрации (проверка даты рождения) закрывает COPPA + GDPR Art.8 + DSA Art.28.

| Требование | Реализация | Статус |
|---|---|---|
| Нет сторонних аналитических SDK для детей | Зависит от tech stack | ⚠️ Нужна проверка SDK |
| Нет сторонней рекламы для детей | Age gate 18+ при регистрации блокирует несовершеннолетних | ✅ |
| Parental gate для внешних ссылок | Не применяется — только 18+ | ✅ Н/П |
| Запрет сбора IDFA у детей | Age gate 18+ | ✅ |

### §2.3.6 Age Rating — Возрастной рейтинг

| Требование | Статус |
|---|---|
| Честно ответить на вопросы о возрастном рейтинге в App Store Connect | 🔄 Административный процесс |
| Если приложение допускает 13+, рейтинг должен отражать контент (обычно 12+ или 17+) | ⚠️ Уточнить при подаче |
| UGC-приложения обычно получают рейтинг 17+ из-за потенциального контента | ⚠️ Учесть при подаче |

### §2.5.13 Биометрическая аутентификация

| Требование | Статус |
|---|---|
| Если используется распознавание лица — использовать LocalAuthentication, не ARKit | ✅ (если используется Face ID) |
| Альтернативный метод аутентификации для пользователей < 13 лет | ⚠️ Нужна проверка |

### §2.5.14 Запись активности пользователя

| Требование | Статус |
|---|---|
| Явное согласие пользователя + визуальный/аудио индикатор при любой записи (камера, микрофон, экран) | ⚠️ При добавлении stories/video features — обязательно |

## ЧАСТЬ 3. ДИЗАЙН (Design)

### §4.5.4 Push Notifications — Push-уведомления

| Требование | Реализация | Статус |
|---|---|---|
| Push **не должны быть обязательны** для работы приложения | Все функции работают без push | ✅ |
| Push для промо/маркетинга — **только с явного opt-in** | Notifications → Email/Push opt-in | ✅ |
| Должна быть возможность **отписаться от промо push** внутри приложения | Notifications settings | ✅ |
| Нельзя отправлять sensitive personal data через push | Нет sensitive data в push | ✅ |

### §4.8 Login Services — Вход через сторонние сервисы

> **Это одно из самых часто нарушаемых правил — автоматический отказ при нарушении.**

| Требование | Реализация | Статус |
|---|---|---|
| Если приложение поддерживает Google / Facebook / Twitter login → **Sign in with Apple обязателен** | Login & Security → Sign in with Apple | ✅ |
| Альтернативный login должен: не собирать лишнего, разрешать скрыть email, не использовать данные для рекламы | Sign in with Apple = соответствует | ✅ |

## ЧАСТЬ 4. ЮРИДИЧЕСКИЕ ТРЕБОВАНИЯ (Legal) — §5. Полный разбор

### §5.1.1 Data Collection and Storage — Сбор и хранение данных

> Это самый детальный и критически важный раздел для социальной сети.

#### §5.1.1(i) Privacy Policy — Политика конфиденциальности

| Что Privacy Policy ОБЯЗАНА содержать | Статус | Примечание |
|---|---|---|
| Какие данные собираются, как и для каких целей | ✅ (предполагается) | Нужна проверка полноты |
| Список всех третьих сторон, с которыми данные передаются | ⚠️ Нужна проверка | Аналитика, рекламные сети, SDK |
| Защита данных третьими сторонами на том же уровне | ⚠️ Нужна проверка vendor agreements | |
| **Политика хранения / удаления данных** (data retention/deletion policy) | ❌ **ПРОБЕЛ — нигде не прописана** | GDPR Art.25(2) + App Store §5.1.1(i) |
| Как пользователь может **отозвать согласие** | ✅ Your Data → Withdraw consent | |
| Как пользователь может **запросить удаление данных** | ✅ Account → Delete account | |

> ❌ **Критический пробел**: Apple требует, чтобы Privacy Policy явно описывала **data retention/deletion policy**. Это отсутствует и в Privacy Policy, и в разделе Your Data. Нужно добавить: сроки хранения при активном аккаунте, при деактивации, после удаления.

#### §5.1.1(ii) Permission — Разрешения

| Требование | Статус |
|---|---|
| Получить согласие пользователя перед сбором данных, даже если данные анонимны | ⚠️ Pre-permission screen нужен (также требование Google Play) |
| Платный функционал **не зависит** от предоставления разрешений | ✅ |
| Пользователь может легко **отозвать согласие** | ✅ Your Data → Withdraw consent |
| Purpose strings: чётко и полно описывают использование данных | ⚠️ Зависит от iOS implementation |

#### §5.1.1(iii) Data Minimization — Минимизация данных

| Требование | Статус |
|---|---|
| Запрашивать доступ только к данным, необходимым для **основного функционала** | ✅ Только нужные поля |
| Использовать out-of-process picker (для Photos, Contacts) вместо полного доступа | ⚠️ Зависит от iOS implementation |
| **Не запрашивать микрофон** для функций, которые его не используют | ✅ (предполагается) |

#### §5.1.1(iv) Access — Управление доступом

| Требование | Статус |
|---|---|
| Не манипулировать пользователем для получения согласия | ✅ |
| Предоставить **альтернативу** для пользователей, отказавших в разрешении | ⚠️ Нужна проверка UX flows |
| Например: если нет доступа к Location → ручной ввод адреса | — (Location не используется) |

#### §5.1.1(v) Account Sign-In & Deletion — Аккаунт

| Требование | Статус |
|---|---|
| Если есть создание аккаунта → **обязательно предложить удаление** внутри приложения | ✅ Account → Delete account |
| Приложение не должно **требовать личные данные** для базового использования | ✅ Опциональные поля |
| Механизм **отзыва социальных credentials** (Facebook/Google) внутри приложения | ⚠️ Login & Security → нужна кнопка «Отключить Google/Facebook» |
| Нельзя хранить credentials/tokens социальных сетей вне устройства | 🔄 Backend requirement |

> ❌ **Пробел**: нужна явная кнопка отключения каждого стороннего login-провайдера в Login & Security.

### §5.1.2 Data Use and Sharing — Использование и передача данных

#### §5.1.2(i) App Tracking Transparency (ATT)

| Требование | Статус |
|---|---|
| Для отслеживания пользователей **между приложениями/сайтами** → обязательно использовать ATT API (NSUserTrackingUsageDescription) | ❌ **Нужна проверка — если используется реклама/аналитика** |
| Приложение **не может требовать** включения push, location, tracking для доступа к функциям | ✅ |
| Явное разрешение перед передачей данных третьим сторонам, **включая third-party AI** | ❌ **Нужно добавить согласие при передаче данных в AI** |

> ❌ **Критический пробел**: если Bestme использует сторонние аналитические SDK (Firebase, Mixpanel, Amplitude и т.п.) или рекламные сети — **ATT-диалог обязателен** для iOS 14.5+. Без него Apple отклонит приложение.

#### §5.1.2(iii) User Profiles

| Требование | Статус |
|---|---|
| Нельзя тайно строить профиль пользователя на основе собранных данных | ✅ recommendations_opt_out |
| Нельзя деанонимизировать пользователей на основе «анонимных» данных | ✅ |

#### §5.1.2(iv) Contacts/Photos Data

| Требование | Статус |
|---|---|
| Нельзя использовать данные из Contacts/Photos для создания базы данных для продажи | ✅ |
| Нельзя контактировать людей через данные из Contacts без явного действия пользователя | ✅ |

### §5.1.4 Kids — Данные детей

| Требование | Реализация | Статус |
|---|---|---|
| Обязательно соблюдать COPPA, GDPR, применимые законы для детей | ✅ (проектируется) | |
| Если приложение собирает данные детей → Privacy Policy обязательна | ✅ Privacy Policy | |
| **Нет third-party analytics** для пользователей из Kids Category | ✅ Н/П — только 18+ | |
| **Нет third-party advertising** для детей | ✅ Blocking по age gate 18+ | |
| При сборе данных детей → только имя + email | ✅ Н/П — только 18+ | |

### §5.1.5 Location Services — Геолокация

| Требование | Статус |
|---|---|
| Location Services только если напрямую связаны с основным функционалом | — Location не используется |
| Объяснить цель в приложении | — |
| Не использовать для экстренных служб или автономного управления транспортом | — |

## ЧАСТЬ 7. ЧЕКЛИСТ ДЛЯ App Review Submission

При каждой подаче в App Review проверить:

### Обязательные пункты Before You Submit

- [ ] Приложение протестировано на устройстве, нет крашей
- [ ] Предоставлен демо-аккаунт (login + password) в App Review Notes
- [ ] Backend-сервисы работают в момент ревью
- [ ] Описаны все неочевидные функции в App Review Notes
- [ ] Metadata точна и не содержит placeholder текста

### UGC Checklist (§1.2) — для каждой подачи

- [ ] ✅ Механизм жалоб на контент работает
- [ ] ✅ Блокировка пользователей работает
- [ ] ✅ Фильтрация неприемлемого контента активна
- [ ] ✅ Контактная информация опубликована в приложении
- [ ] Эти 4 пункта **явно описаны** в App Review Notes

### Privacy Checklist (§5.1) — для каждой подачи

- [ ] Privacy Policy ссылка в App Store Connect metadata
- [ ] Privacy Policy ссылка внутри приложения (Help или Your Data)
- [ ] Privacy Nutrition Labels заполнены в App Store Connect
- [ ] ATT диалог реализован (если используется tracking)
- [ ] Sign in with Apple реализован (если есть 3rd-party login)
- [ ] Удаление аккаунта доступно внутри приложения
- [ ] Data retention/deletion policy описана в Privacy Policy

### Kids & Age Rating (§1.3/§2.3.6/§5.1.4)

- [ ] Age rating честно выставлен в App Store Connect (18+ приложение)
- [ ] SDK для аналитики/рекламы не собирают данные детей (age gate 18+ обеспечивает это)
- [ ] Нет targeted ads без явного согласия пользователя

## ПРИЛОЖЕНИЕ. Разбор конкретных пунктов §5.1.1(i) — что Privacy Policy Bestme должна содержать

По требованию Apple §5.1.1(i), Privacy Policy **обязана чётко и явно** объяснять:

| Пункт | Что нужно написать | Статус |
|---|---|---|
| Какие данные собираются | Полный список: имя, email, дата рождения, контент, IP, device ID, usage data | ⚠️ Проверить полноту |
| Как данные собираются | При регистрации, использовании, через SDK | ⚠️ |
| Все цели использования | Аутентификация, персонализация, аналитика, реклама (если есть) | ⚠️ |
| Третьи стороны, получающие данные | Список SDK (Firebase, Amplitude и т.д.) + их privacy level | ⚠️ Нужен список |
| **Политика хранения** (retention) | «Данные хранятся X лет / до удаления аккаунта» | ❌ **Отсутствует** |
| **Как запросить удаление** | «Account → Delete account» или «contact@bestme.com» | ✅ |
| **Как отозвать согласие** | «Your Data → Withdraw consent» | ✅ |
